# LifeMentor — личная ИИ-наставница развития

LifeMentor — это «личная ОС развития»: приложение, которое запоминает вас (структурированная,
редактируемая память ИИ), строит модель ваших целей и ценностей, планирует день детерминированным
планировщиком, ведёт обучение с интервальным повторением, следит за навыками и прогрессом,
показывает новости с объяснением «почему это важно для вас» и синхронизируется между Windows и
Android.

Принципы, зашитые в архитектуру:

- **Local-first.** SQLite — единственный источник правды (WAL, транзакции, FK, busy_timeout,
  миграции, проверки целостности). JSON — только для экспорта/импорта/бэкапов/снимков/обмена с ИИ.
- **Безопасность от сбоев.** Каждое критическое изменение немедленно коммитится: INSERT → COMMIT →
  подтверждение в UI → синхронизация позже. Данные переживают kill/reboot/отключение сети.
- **ИИ без SQL.** Провайдер-абстракция (OpenAI / Anthropic / Google / локальный), ключи — только на
  сервере (gateway), ИИ работает через контролируемые инструменты (`create_goal`, `create_task`,
  `reschedule`, `save_memory`, …), а не через запросы к базе.
- **Никаких поддельных функций.** Если фича заявлена — она работает; если нет сети — приложение
  честно показывает офлайн-состояние, а не выдуманные данные.
- **Незаметная инфраструктура.** Контент-скрипты пользователя: установщик `.exe` (Windows) и `.apk`
  (Android); Docker/Node/PostgreSQL/CLI пользователь не видит.

## Репозиторий (monorepo, npm workspaces)

```
packages/core/   Движок: SQLite-схема (49 таблиц), драйверы (node:sqlite, sql.js/WASM, Tauri,
                 Capacitor), репозитории, сервисы (goals, tasks, calendar, projects, skills,
                 learning, knowledge, memory, context, news, notifications, progress, sync,
                 backup, recovery, auth, onboarding, planner, strategy), ИИ-оркестратор +
                 Context Engine + инструменты.
apps/server/     LifeMentor Server (Fastify, порт 8787): auth (scrypt, JWT, refresh-ротация,
                 устройства), синхронизация (push/pull с курсором и конфликтами), AI gateway
                 (ключи провайдеров не покидают сервер), новостной RSS-поллер (8 реальных лент,
                 30 мин, дедупликация по url-hash, urgency, what/why/context), push-уведомления
                 (VAPID Web Push + очередь для polling, срочные новости с дневным лимитом),
                 облачная копия (шифртекст + sha256, сервер не может прочитать), health.
apps/web/        Веб-приложение (React 18 + Vite): 13 экранов + Auth + двухэтапный onboarding.
                 В браузере — реальный SQLite в WebAssembly (sql.js), образ БД хранится в
                 IndexedDB; auth/sync/AI/news идут через сервер. Тот же бандл работает внутри
                 обоих шеллов (bootstrap сам определяет окружение).
apps/desktop/    Windows-шелл (Tauri 2): src-tauri на Rust — rusqlite (WAL) на стороне ОС,
                 нативное планирование уведомлений, NSIS-установщик. Сборка: `npm run shell:windows`.
apps/mobile/     Android-шелл (Capacitor 8): android/ Gradle-проект, платформенный SQLite,
                 системные уведомления (работают в фоне), Filesystem+Share для экспорта.
                 Сборка: `npm run shell:android` + `gradlew assembleRelease`.
docs/            Проектирование: продуктовая спецификация, выбор стека, архитектура, схема БД,
                 синхронизация, сбойностойкость, ИИ-оркестрация, планировщик, уведомления,
                 упаковка/сборка (docs/11-packaging.md), MVP-состав, roadmap (docs/10-roadmap.md).
```

## Быстрый старт (для разработки)

```bash
npm install            # зависимости (workspace: core, server, web, mobile, desktop)
npm test               # 148 автотестов (core + server + web bootstrap + UI-сквозные сценарии
                       # + контракты драйверов Tauri/Capacitor)

npm run dev --workspace @lifementor/server   # API на :8787
npm run dev --workspace @lifementor/web      # веб-приложение на :5173 (прокси /v1 → :8787)
```

Откройте http://localhost:5173 → регистрация → onboarding (опросник → адаптивное интервью →
профиль «Вот как я тебя понял» → подтвердить). Дальше — Дашборд/Сегодня/Цели/Обучение/Память/…

Переменные окружения сервера — в `.env.example`: `JWT_SECRET` (без него — одноразовый секрет с
предупреждением), `DATABASE_PATH` (по умолчанию `data/server.sqlite`), ключи провайдеров
(`OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `GOOGLE_API_KEY`) — без них gateway работает на локальном
эвристическом провайдере (deterministic, офлайн). Для стабильных push-подписок — VAPID-пара
(`npm run vapid:keys --workspace @lifementor/server`).

## Что уже работает

- Двухэтапный onboarding: универсальный опросник → ИИ-анализ → адаптивное интервью (только
  вопросы, улучшающие модель, ≤ 7) → обзор профиля с подтверждением.
- Структурированная память ИИ: источник (user_provided / ai_inferred / system_observed),
  статус (confirmed / inferred / uncertain), «Что ИИ знает обо мне» с редактированием/удалением/
  подтверждением/отметкой «неверно».
- Цели иерархией (долгосрок → среднесрок → проект → навык → задача), проекты с вехами и
  задачами, навыки по доказательствам, карта знаний с разрывами, обучение (пути, темы, активное
  вспоминание, интервальное повторение SM2).
- Детерминированный планировщик: жёсткие события (экзамен в 14:00) не перемещаются;
  бюджет свободного времени по умолчанию 1–2 ч; строгий режим спрашивает причину удаления;
  перепланирование оставшегося дня; невозможных расписаний не бывает.
- Синхронизация: очередь операций, push/pull по курсору, детерминированное разрешение простых
  конфликтов, явный диалог для важных («изменено на двух устройствах — какую версию оставить?»).
- Бэкапы: автоматические локальные, портативный JSON-экспорт, импорт с проверкой структуры,
  превью изменений и бэкапом перед импортом, удаление аккаунта с экспортом. **Облачная копия**:
  архив шифруется на устройстве (AES-GCM, WebCrypto), на сервере — только шифртекст + sha256;
  загрузка/скачивание/удаление из Настройки → Данные.
- Новости: сервер собирает 8 реальных RSS-лент (мир, геополитика, технологии, ИИ, экономика,
  наука, программирование), помечает срочное, объясняет «что случилось / почему важно /
  контекст», хранит кэш офлайн. Без сети — честный пустой фид, а не выдуманные новости.
- Уведомления: локальный движок (важность + срочность + тихие часы + дневной бюджет, дедупликация)
  + **Web Push**: сервер пушит через VAPID даже при закрытой вкладке (Service Worker), а всё, что
  push не доставил, приходит по polling при следующем открытии. Срочные новости пушатся с жёстким
  дневным лимитом на пользователя. Настройки — в Настройки → Уведомления (включить/отключить/тест).
- Дашборд: «что происходит в моей жизни и что делать прямо сейчас» (сегодняшний план,
  дедлайны, обучение, прогресс, срочные новости).
- Стратегия: слои (3–5 лет → год → квартал → сейчас), неизменяемая история изменений
  (старое/новое/причина/дата).
- **Проверено на уровне UI**: сквозные тесты поднимают настоящий `App` (React + Provider + экраны)
  в jsdom поверх реального `LifeMentorApp` с файлом SQLite во временной папке: onboarding целиком
  проходится через DOM, задача создаётся и выполняется, наставник реально вызывает инструмент,
  план не ставится поверх экзамена, а после перезапуска процесса все подтверждённые данные на месте.
- **Шеллы готовы к сборке**: один и тот же бандл в Windows (Tauri 2, нативный SQLite через
  rusqlite, системные уведомления с планированием) и Android (Capacitor 8, платформенный
  SQLite, фоновые системные уведомления). Контракты драйверов покрыты тестами. Сборка —
  одна команда на машине с Rust/JDK или тегом `v*` в CI: `docs/11-packaging.md`.

## Уведомления (Web Push + FCM)

Два транспорта, один гарантированный путь. **Web Push** (браузер): VAPID, service worker,
push при закрытой вкладке. **FCM** (Android): сервер шлёт через FCM v1 API (RS256 по сервисному
аккаунту), urgent-уведомления видны из закрытого приложения, остальные проходят локальный
шлюз (бюджет / тихие часы) при следующем foreground. Общее: очередь на сервере +
polling-fallback — любое уведомление дойдёт, даже если push не сработал. Включить FCM:
Firebase-проект для `ai.lifementor.app` + сервисный аккаунт на сервере — `docs/11-packaging.md`
(раздел FCM).
